Slack integration

Your team stays in Slack. Agents stay in sync.

Slack Connect mirrors bound channels into Neural Junkie with two-way threading: @mentions and channel lines route to the agent you choose — Assistant, custom experts, repo agents, or any configured Claude / GPT / Gemini / Ollama backend. Personal inbox (beta.21): DM the NJ bot from Slack mobile; replies land in a private hub channel. Optional forwarding rules and away-mode human DM replies keep you covered when you are not at the desk.

  • Per-channel policy — always-on, questions-only, or @mention routing.
  • Mobile → agent — DM the bot; pick which agent answers in NJ.
  • Forward from channels — @mention, nj: prefix, or reaction emoji rules.
  • Real names in NJ — Slack channels show as #cursor-test, not opaque IDs.

Install-and-go local AI

Download once. Run locally. Wizard handles Ollama.

macOS installers bundle the Ollama runtime; Linux and Windows use slim builds and the setup wizard Install Ollama on first launch. Complete the wizard, pull a default model once, and your agents run on your hardware — private by default, cloud optional. After first run, browse more models in the built-in Model library.

  • Auto-start — production app runs ollama serve with models in app data.
  • Linux & Windows — wizard installs Ollama (winget, silent installer, or install.sh).
  • Model library — curated Ollama + Hugging Face grid (⇧⌘M) when you want more than the default.
  • Cloud when you need it — Claude, OpenAI-compatible APIs, and per-agent routing in Settings.

Hardware requirements

The app is small. The models are not.

Neural Junkie ships as a ~15 MB desktop app plus an Ollama runtime (~1–2 GB — bundled on macOS, wizard-installed on Linux/Windows). Your first local pull for software development defaults to qwen2.5-coder:14b (~9 GB) and qwen2.5:7b (~4.5 GB) — roughly 15–20 GB total on disk before you chat. The setup wizard reads your RAM and recommends model tags; Settings shows estimated disk and suggested RAM per model.

TierRAMDeveloper primary
minimal< 8 GBqwen2.5-coder:7b / llama3.2:3b
light8–15 GBqwen2.5-coder:7b
recommended16–31 GBqwen2.5-coder:14b
heavy32 GB+14B + LoRA bases / larger models
  • Multi-agent ≠ multi-model — specialists share one Ollama backend; you pay latency, not six 14B loads.
  • Hybrid by design — local iteration, cloud for hard reviews when 14B is not enough.
  • Honest limits — collab variance on local models, bounded repo indexes, single local hub — see known issues.

How you actually work in it

Same habits as team chat — with agent-native superpowers for individuals and groups.

Routing & context

  • @mentions by agent name or type so the right specialist answers.
  • Threads for side discussions without spamming the channel.
  • Agent review — pull a second opinion by @mentioning another agent in a thread reply.
  • Assistant flows — reminders, tasks, notes, meeting ingest, and workspace-grounded follow-ups.

Always-on helpers

  • Moderator — command help, product guidance, and a safety net when questions sit unanswered.
  • Assistant — tasks, reminders, notes, meeting-oriented commands, and scoped workspace context when you opt in.
  • First-run setup wizard — get providers and agents configured without reading a novel first.
  • Tool approvals — gate risky agent tool use where your stack requires it.

Ship with confidence

Opinionated defaults for teams that want speed and guardrails.

  • Single-binary sidecar packaging — ship a .dmg or AppImage without a fragile pile of services.
  • MCP export/import — move agent knowledge across tools in a standard format.
  • Auto-updates via the Tauri updater — stay current without chasing tarballs.
  • Session persistence on the hub — channels and state come back after restarts (with sensible pruning).
  • Markdown & Mermaid in the desktop — diagrams and formatted answers where they help.
  • Web + terminal + CLI — same hub speaks to the desktop, browser chat, make chat, and automation via the Go CLI.
