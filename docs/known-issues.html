Known issues & limitations

Open beta means real gaps. This page lists what we know is wrong, flaky, or intentionally scoped — and we remove items when they are fixed. Last updated June 7, 2026 for v1.0.0-beta.27. Maintainer copy: docs/KNOWN_ISSUES.md (keep in sync).

Collaboration

Multi-agent collab is the hardest surface to make reliable. See also Collaboration guide and COLLABORATION.md.

  • Active Planning sometimes yields zero tasks

    Live harness scenarios can finish discussion but fail assert_plan: tasks=0 — plan parser / discussion → plan artifact. Affected names include plan-dependency-prose-regression, plan-distinct-deliverables-same-agent, plan-phoenix-combined-regression. Sweep log (2026-06-02).

  • Active Deliverable file too small for harness

    execution-no-stack-commands may fail when findings.md exists but content is below assertion thresholds.

  • Investigating Solo vs collab parity

    solo-vs-collab-parity — solo channel leg did not land a file before timeout in a spot check; full serial sweep pending.

  • Investigating Phoenix-style planning scenario

    resource-api-schema-planning not completed in last batch run (aborted mid-sweep).

  • Limitation Chat does not write files

    Execution success means approved file-change proposals, not polished markdown in the thread. TASK_STATUS: completed alone does not create files.

  • Limitation Workspace confirmation gate

    After you approve the plan, task prompts wait until you Continue in the desktop or run /ack-collab-workspace. Until then, execution can look “stuck.”

  • Limitation Model variance

    Local Ollama models differ in silence, speed, and plan quality. The hub enforces phase budgets and fallbacks; it cannot force a perfect task list from every model.

  • Limitation Smart routing scope

    Collaboration smart routing applies to execution tasks only — not planning turns or normal channel chat.

Chat & context

  • Active Context model v2 edge cases

    Chat/Code composer mode and workspace visibility shipped in beta.21 — report bad answers when asked whether agents can see your workspace. CONTEXT_MODEL.md

  • Limitation Bounded message history

    Per-channel history is pruned over time; the hub is not a full searchable archive. Session metadata restores from last-session.json.

Integrations

  • Limitation Slack needs local hub

    Socket Mode bridge runs in-process — the hub must be running on your machine.

  • Limitation Confluence setup cost

    Doc agents need Cloud credentials, indexing time, and reasonable space size for good answers.

Desktop, IDE & packs

  • Limitation Web UI is thin

    Browser chat at / lacks the full desktop workspace, palette, and file-approval flows.

  • Limitation Git requires dev pack

    In-app Git needs the Software development pack, git on PATH, and a git workspace.

  • Limitation IDE v2/v3 beta

    Layout presets, diagnostics, and Ask/Agent routing are evolving. IDE_V3.md

  • Limitation First enabled pack sets layout

    With multiple domain packs on, the first pack you enable picks IDE vs team layout.

  • Active Implement deterministic fallback

    Live implement scenarios still rely on deterministic tailwind/App repairs when local models emit prose-only replies. Hub logs: deterministic_impl_fallback, app_theme_repair.

  • Active Parity-stable hub OOM

    make test-parity-stable back-to-back sweeps can OOM-kill the regression hub on memory-limited hosts. Restart hub between sweeps; see docs/testing/parity-stable-*.log.

Hub, agents & providers

  • Limitation Single hub instance

    No distributed or multi-region deployment model yet.

  • Limitation Standalone agents poll

    cmd/agent processes use HTTP polling; in-process hub agents get lower-latency push delivery.

  • Limitation Pause ≠ abort

    /pause-agent updates roster state; it does not cancel an active LLM request.

  • Limitation Tool calling varies by provider

    MCP tools are best supported on Ollama (selected flows) and Claude; LM Studio / generic OpenAI-compat is limited.

  • Limitation Ollama model download

    Installers bundle the Ollama runtime only; models are pulled on first use (one-time download, can be several GB).

  • Limitation macOS Gatekeeper

    Builds are ad-hoc signed, not notarized — use Right-click → Open on first launch if blocked.

How we test (and close items)

  • Go tests — orchestrator, plan parsing: make test-collab-plan, make collab-smoke
  • Live collab scenarios — make collab-scenario SCENARIO=…; matrix: collab-matrix.tsv
  • Chat scenarios — make chat-scenarios-regression (beta.21+)

When a scenario flips to PASS, delete the matching <li> here and the row in KNOWN_ISSUES.md, then note the fix in release notes.
