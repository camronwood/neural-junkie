Known issues & limitations

Open beta means real gaps. This page lists what we know is wrong, flaky, or intentionally scoped — and we remove items when they are fixed. Remaining entries are intentional limitations. Several UX gaps were closed in the limitations sprint (layout owner picker, workspace gate banners, pause abort, channel export). Last updated June 17, 2026 (v1.2.0-beta.1 — IDE v4; stable checklist in STABLE_RELEASE_CHECKLIST.md). Maintainer copy: docs/KNOWN_ISSUES.md (keep in sync).

Collaboration

Multi-agent collab is the hardest surface to make reliable. See also Collaboration guide and COLLABORATION.md.

  • Limitation Chat does not write files

    Execution success means approved file-change proposals, not polished markdown in the thread. TASK_STATUS: completed alone does not create files.

  • Limitation Model variance

    Local Ollama models differ in silence, speed, and plan quality. The hub enforces phase budgets and fallbacks; it cannot force a perfect task list from every model. Mitigation: Settings → Collaboration planning provider for optional cloud/larger-model planning turns.

  • Limitation Smart routing scope

    Collaboration smart routing applies to execution tasks only — not normal channel chat. Planning can use a separate optional planning provider in Settings.

Chat & context

  • Limitation Bounded message history

    Per-channel history is capped (5000 messages) and age-pruned after 24h unless marked durable in channel info. SQLite sidecar + Export history — not a full in-app search archive.

Integrations

  • Limitation Slack needs local hub

    Socket Mode bridge runs in-process — the hub must be running on your machine.

  • Limitation Confluence setup cost

    Doc agents need Cloud credentials, indexing time, and reasonable space size for good answers.

Desktop, IDE & packs

  • Limitation Web UI is thin

    Browser chat at / lacks the full desktop workspace, palette, and file-approval flows.

  • Limitation Git requires dev pack

    In-app Git needs the Software development pack, git on PATH, and a git workspace.

  • Limitation macOS ad-hoc signing

    GitHub Release macOS builds are ad-hoc signed until Apple Developer credentials are available. First launch may require Right-click → Open. Planned fix: v1.2.1 notarized builds.

Hub, agents & providers

  • Limitation Single hub instance

    No distributed or multi-region deployment model yet.

  • Limitation Tool calling varies by provider

    MCP tools are best supported on Ollama (selected flows) and Claude; LM Studio / generic OpenAI-compat is limited.

How we test (and close items)

  • Go tests — orchestrator, plan parsing: make test-collab-plan, make collab-smoke
  • Live collab scenarios — make collab-scenario SCENARIO=…; matrix: collab-matrix.tsv (21/21 PASS)
  • Chat regression — make chat-scenarios-regression (workspace visibility, closure, echo)
  • Implement parity — make implement-scenarios, make test-parity-stable (3× with hub restart)

When a scenario flips to PASS, delete the matching <li> here and the row in KNOWN_ISSUES.md, then note the fix in release notes.
